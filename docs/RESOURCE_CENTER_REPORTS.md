# Resource Center HTML stat reports (issue #762)

Director's **Exports → Quizbowl Resource Center → Prepare for HSQuizbowl** (issue #766)
produces the HTML files a director uploads
to the Quizbowl Resource Center (`hsquizbowl.org/db`). Per current ACF statkeeping guidance,
the Resource Center accepts reports generated by **YellowFruit or SQBS**; this exporter targets
that accepted structure while deriving every number from QBSheet's canonical stats engine.

## Reference shape

A current accepted YellowFruit report documents the six-view public surface:

- https://hsquizbowl.org/db/tournaments/10615/stats/all_games/
- Views: **Standings · Individuals · Scoreboard · Team Detail · Player Detail · Round Report**
- The public navigation exposes **no separate Stat Key view**.

The reference is also pinned in code as `resourceCenterReference`
(`packages/tournament-formats/src/resourceCenterReport.ts`), which structural tests assert.

## What the exporter produces

`buildResourceCenterReport(snapshot)` (formats) / `buildCanonicalResourceCenterReport(state)`
(Director) return one file per semantic upload role:

| Role (`kind`)  | File                       | Required upload slot             |
| -------------- | -------------------------- | -------------------------------- |
| `standings`    | `<base>_standings.html`    | yes                              |
| `individuals`  | `<base>_individuals.html`  | yes                              |
| `scoreboard`   | `<base>_games.html`        | yes                              |
| `teamDetail`   | `<base>_teamdetail.html`   | yes                              |
| `playerDetail` | `<base>_playerdetail.html` | yes                              |
| `rounds`       | `<base>_rounds.html`       | yes                              |
| `statKey`      | `<base>_statkey.html`      | **no** — optional SQBS companion |

Suffixes mirror the filenames QBSheet's own SQBS serializer advertises
(`packages/tournament-formats/src/sqbs.ts` settings section). The Resource Center upload
walkthrough maps its `Scoreboard` field to the report ending in `_games.html`.

Each file carries its semantic role in code (`kind`, `requiredForResourceCenter`) — never
identified by filename parsing. `index.html` stays with the general printable QBSheet report
and is not an upload slot.

## Rules that keep reports honest

- **Canonical snapshot only.** Accepted/current results, supersession/corrections, cancelled
  games excluded, forfeits, ties/overtime, final-placement ranks, and scoring definitions all
  arrive via the snapshot. There is no Resource Center-specific calculator.
- **Unknown is not zero.** Missing detail renders as `—`; rates without a known denominator
  are withheld, not estimated.
- **Dynamic stat key.** The companion documents only abbreviations this tournament's rules
  actually emit (answer tiers and point values, PPG vs normalized Pts/X, PPB/bonus fields,
  bouncebacks/lightning/overtime only when applicable). Mixed scoring definitions are
  disclosed, not merged.
- **Escaping.** Tournament/team/player names are HTML-escaped in every file; the base name
  is sanitized to one stable, filesystem-safe prefix (`sanitizeResourceCenterBaseName`).
- **Director scope.** The Director adapter forces the full six-view page set even when the
  printable report options narrow pages, so upload roles and cross-links never drop.

## Prepare-for-HSQuizbowl workflow (issue #766)

**Exports → Quizbowl Resource Center → Prepare for HSQuizbowl** is the single
operator path from accepted results to upload files, for simple and multi-phase
tournaments alike:

1. **Report sets.** Simple tournaments show their one set with team/game/round
   counts and no configuration. Multi-phase tournaments default to the
   recommended preset (every phase plus combined, per ACF guidance) with
   phases-only and combined-only available, and each scope shows teams /
   accepted games / rounds before anything is written.
2. **Report names.** Each set defaults to its scope label (`Prelims`,
   `Playoffs`, `Combined`, `Overall` for single-stage) and the director may
   rename it. Display labels are HTML-escaped where rendered; filesystem
   filenames stay on the separate sanitized base prefix, so renaming never
   destabilizes files. Duplicate display labels warn without blocking.
3. **Preflight.** Every selected set runs the #764 validator. The dialog shows
   **Ready to save** (preflight passed — still preparation, not publication),
   warnings that ride along through the save, or **fix-required** blockers that
   refuse it. Each blocker links at its Director fix where an operator-side fix
   exists (results, rosters, rules, settings); structural generator problems
   offer no link because no Director surface fixes them.
4. **Save files.** One ZIP per operation on both browser and native Director
   (the native shell offers single-file save only, so there is no folder
   export). Both flows say to extract the ZIP and choose each HTML file — the
   Resource Center takes separate HTML files, never the ZIP. The dialog shows
   the generated timestamp and a short content revision per package and per set,
   so a regeneration after a correction is distinguishable from a stale file.
   The confirmation says **Saved — not yet published**; nothing here marks a
   report uploaded or published.
5. **Upload handoff.** An `Open Quizbowl Resource Center` link, the
   owner-account reminder, the exact navigation path (`Edit tournament listing`
   → `Manage stat reports` → `Add stat report`), and a per-set mapping table
   from Resource Center field names to generated files. The mapping is
   generated from each file's semantic role, never filename heuristics; only
   the Scoreboard → `*_games.html` row is attested by a public walkthrough.

## Multi-phase scopes (issue #763)

Director's **Exports → Quizbowl Resource Center** offers publishable scopes from the
explicit phase model (never round-number ranges):

- one set per non-archived phase, in phase order;
- a `Combined` set for the entire tournament (`Overall` for single-stage);
- single-stage tournaments expose only the combined scope — no phase chooser.

The recommended preset (**every phase + combined**) matches current ACF guidance;
`selected phases only` and `combined only` are also available. The dialog previews
the number of report sets and files before export, and one operation writes a single
ZIP containing every selected set under its own stable base prefix:

- `my-tournament-prelims_standings.html`
- `my-tournament-playoffs_standings.html`
- `my-tournament-combined_standings.html`

Scope policy:

- Per-phase games are exactly the accepted games in that phase's rounds (byes,
  cancelled rows, superseded corrections, and invalid legacy records excluded;
  forfeits counted; replays collapsed to the current accepted truth).
- Dropped teams keep their valid historical games for opponents but leave
  standings rows, matching Director/Live.
- Carryover phases include eligible prior-phase games in standings only; the
  Scoreboard lists stage games, so no game is duplicated in detail. The label
  gains `· including carryover` and the set warns explicitly.
- Tiebreaker-packet games stay in the Scoreboard as explicit results but do not
  decide standings unless `tiebreakerCountsStatistically` is set.
- `finalPlacement` overrides order in the combined set only.
- Within one phase, pools are retained as division metadata; the combined set
  omits pool assignments with an explicit warning instead of flattening
  changing pools into one global division.
- Each scope uses only its own games' scoring definitions. Mixed definitions
  render one semantic answer column with explicit notes (never merged by
  number or silently re-valued); the combined set additionally warns and
  points at the phase sets.

## Compatibility status

Structure is tested against the reference contract (document shell, per-role content,
escaping, link integrity, suffixes), **not** byte-for-byte against SQBS/YellowFruit output.

Issue **#764** added the validation layer that makes “ready” a checked state:

- `preflightResourceCenterReport`
  (`packages/tournament-formats/src/resourceCenterPreflight.ts`) runs blocking errors
  vs warnings over every export; Director refuses the download while anything blocks
  and announces warnings alongside a successful one.
- Genuine YellowFruit 4.0.18 output plus an honestly-labeled SQBS structural reference
  live under `packages/tournament-formats/tests/fixtures/resource-center/` with
  provenance; `resourceCenterCompatibility.test.ts` pins parser-relevant structure
  across all three generators without brittle snapshots.
- `resourceCenterCompatibility.liveUploadVerified` stays `false` and the Prepare
  workflow never claims “compatible”, “upload-ready”, or any published/uploaded
  success state — readiness is always save-scoped (“Ready to save”) — until the
  manual live-upload smoke test in `docs/RESOURCE_CENTER_SMOKE_TEST.md` succeeds.

> The “Resource Center compatible” label still awaits that real-upload smoke test,
> which proves generated files are accepted. Network upload itself is an explicit
> non-goal of #762/#764 and is not implemented here (see #767).
